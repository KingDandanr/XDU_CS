按“项目结构 -> 核心模块 -> 运行流程 -> 结果文件 -> 演示命令”来讲。

**1. 整体结构**

> 本项目主要使用 Python 实现，整体分为环境建模、算法训练、模型评估、可视化演示和结果分析几个部分。代码入口文件包括 train.py、train_dqn.py、evaluate.py、demo.py 和 compare_training.py。核心代码放在 src 目录下，实验结果统一保存在 artifacts 目录中。

对应结构：

```
src/ ├─ envs/ │  ├─ vehicle_avoidance_env.py │  └─ scenario_library.py ├─ training/ │  ├─ ppo_trainer.py │  └─ dqn_trainer.py └─ evaluation/   ├─ evaluator.py   └─ demo_runner.py
```

**2.环境模块**
重点讲 vehicle_avoidance_env.py。

> vehicle_avoidance_env.py 是整个项目的核心环境文件，它基于 Gymnasium 接口实现。环境中定义了车辆位置、目标点、障碍物、动作空间、状态空间和奖励函数。每次智能体执行一个动作后，环境会更新车辆位置和动态障碍物位置，然后判断是否到达目标、是否碰撞，并返回新的状态和奖励。

> 状态向量包括车辆当前位置、目标相对位置、车辆到边界的距离，以及最近 3 个障碍物的相对位置、半径和速度信息。

> 动作空间是 8 个离散方向：右、右上、上、左上、左、左下、下、右下。这样既能覆盖二维平面主要运动方向，又便于和 DQN 进行对比，因为 DQN 更适合离散动作空间。：

> 奖励函数包括接近目标的正奖励、每步移动的小惩罚、接近障碍物的安全惩罚、碰撞的大惩罚和到达目标的大奖励。这样可以同时引导车辆尽快到达目标并避免碰撞。

**3. 场景模块**
对应 scenario_library.py。

> scenario_library.py 用来集中管理实验场景，目前设计了 5 个场景，包括简单静态、密集静态、动静混合、窄通道和动态交叉场景。每个场景都定义了地图大小、起点、目标点、最大步数和障碍物配置。

```
static_easy：简单静态障碍 static_dense：密集静态障碍 mixed_dynamic：动静混合障碍 narrow_passage：窄通道障碍 dynamic_crossing：动态交叉障碍
```

**4. 训练模块**
PPO 对应：

ppo_trainer.py

DQN 对应：

dqn_trainer.py

你可以说：

> 训练模块主要负责创建环境、配置算法参数、执行训练并保存模型。train.py 是 PPO 的训练入口，train_dqn.py 是 DQN 的训练入口。两个算法使用相同的环境和场景配置，便于公平比较。

PPO 命令：

```
python train.py --scenario mixed_dynamic --timesteps 80000
```

DQN 命令：

bash

```
python train_dqn.py --scenario mixed_dynamic --timesteps 80000
```

训练完成后保存到：

```
artifacts/ppo_<scenario>/ artifacts/dqn_<scenario>/
```

```
final_model.zip monitor.csv training_curve.png training_summary.json
```

你可以解释：

> final_model.zip 是训练好的模型，monitor.csv 是训练日志，training_curve.png 是训练奖励曲线，training_summary.json 是训练摘要。

**5. 讲评估模块**
对应 evaluator.py。

你可以说：

> 评估模块用于加载训练好的模型，在指定场景中运行多个回合，然后统计成功率、碰撞率、平均奖励和平均步数。为了对比 PPO 和 DQN，我还实现了 --compare-all 参数，可以一次性评估所有训练好的模型。

评估命令：

```
python evaluate.py --compare-all --episodes 30
```

```
success_rate：成功率 collision_rate：碰撞率 avg_reward：平均奖励 avg_steps：平均步数
```

**6. 讲演示模块**
对应 demo_runner.py。

你可以说：

> demo.py 用于可视化演示训练好的模型。程序会加载模型，然后实时显示车辆、目标点、障碍物和车辆运动过程。它支持 PPO 和 DQN 两种模型。

PPO 演示：

bash



```
python demo.py --model artifacts\ppo_mixed_dynamic\final_model.zip --scenario mixed_dynamic --delay 0.12
```

DQN 演示：

bash



```
python demo.py --algo dqn --model artifacts\dqn_mixed_dynamic\final_model.zip --scenario mixed_dynamic --delay 0.12
```

注意，你演示时一定要模型和场景对应。比如：

```
artifacts\ppo_static_easy\final_model.zip
```

```
--scenario static_easy
```

不要拿 static_easy 模型去跑 mixed_dynamic，不然容易撞车，老师会一脸“嗯？”。

**7. 讲结果分析**
你可以说：

> 从实验结果看，PPO 在 5 个场景中都取得了 100% 成功率和 0% 碰撞率；DQN 在简单场景和部分动态场景中能完成任务，但在密集静态、动静混合和窄通道场景中表现不稳定。因此本文最终选择 PPO 作为主要算法。

> 本项目的代码主线是：先用 scenario_library.py 定义避障场景，再用 vehicle_avoidance_env.py 构建 Gymnasium 强化学习环境，然后通过 PPO 和 DQN 训练脚本生成模型，最后用评估脚本统计指标、用 demo 脚本展示避障动画。实验结果表明，PPO 在复杂避障场景下比 DQN 更稳定，因此本文选用 PPO 作为主要算法。
